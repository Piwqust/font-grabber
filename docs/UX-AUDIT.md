# Fount — аудит и доработка интерфейса

Дата: 2026-09-05. Объект: локальный сайт http://127.0.0.1:8787/, исходники core/src/web. Расширение браузера не входило в изменения. До начала работы три изменяемых файла сохранены в output/before-ux. Уже существовавшие изменения в extension не принадлежат этому проходу.

## Вывод

Исходный интерфейс не соответствовал .impeccable.md: вместо монохромного списка был рекламный экран с кислотным акцентом, отдельной светлой карточкой формы и сеткой образцов. Проблема была не только визуальной: CSS делал скрытые элементы видимыми, размер образца не применялся, выбор по подписи срабатывал дважды, ошибки превью маскировались запасным шрифтом.

Теперь интерфейс — единый светлый лист на тёмном фоне, с компактной формой, последовательным списком образцов и панелью скачивания. Использованы существующие Geist и Plex Mono, без новых производственных зависимостей. Язык приложения сохранён.

## Проверки

- cargo build --manifest-path core/Cargo.toml --offline — успешно.
- cargo test --manifest-path core/Cargo.toml --offline — 29 тестов прошли.
- node --check core/src/web/app.js — успешно.
- npx prettier --write core/src/web/style.css — CSS отформатирован.
- Chromium: выбор мышью и Space, начальная ссылка пропуска по Tab, редактирование, фильтрация, размер, адаптивность. Настоящее скачивание обнаружило отдельное поведение ниже.
- WebKit: output/playwright/check-flows.js — 29 утверждений прошли; реальный Rust API нашёл 4 локальных шрифта, прокси загрузил превью, скачивание создало архив. ZIP открыт через .NET: Fount-Audit.otf, 58 368 байт.
- Chromium: output/playwright/check-edge-cases.js — 13 утверждений прошли. Искусственные ответы использовались только для ошибки скана, отсутствующего превью, пустого ответа, 81 строки и нулевого результата.
- Изначальная проверка первого Tab в WebKit не прошла: его стандартная навигация отличается от Chrome. После этого отдельно проверена возможность фокусировки skip-link; порядок Tab подтверждён только в Chrome.
- Ошибок JavaScript в успешном полном сценарии WebKit нет. В тестах ошибок HTTP 502 намеренно имитировался.
- Rust выводит два существующих предупреждения: неиспользуемые TransferMethod::label и ScanRequest::webdriver_url.
- Отдельных настроенных JavaScript lint/typecheck-команд в package.json нет.

## Ограничения и оставшийся риск

В Chrome запрос /api/grab получает HTTP 204 с пустым телом и заголовками pragma:no-cache, connection:close. Прямой запрос к серверу и такой же сценарий WebKit возвращают HTTP 200 и корректный ZIP (38 024 байта без переименования). Причина подмены в Chrome не установлена. Процесс IDMMsgHost запущен; перехват менеджером скачивания — гипотеза, не доказательство. Системные настройки не менялись. Теперь этот случай выдаёт ошибку и не создаёт пустой ZIP. Минимальная следующая проверка: сравнить обычное скачивание в Chrome с включённым и временно отключённым перехватом менеджером загрузок.

WebKit проверялся на Windows с уже установленным движком; это не физический iPhone и не Safari на macOS. Сканы произвольных внешних сайтов, режим browser rendering, hosted-развёртывание, реальная запись в произвольную папку и аудит безопасности сервера целиком не проверялись. Для них нельзя делать вывод об исправности по локальному сценарию.

## Восстановление

Исходные app.js, index.html и style.css находятся в output/before-ux. Для возврата достаточно восстановить эти три файла в core/src/web и пересобрать сервер. Архивы прежних веток, расширение браузера и данные пользователя не изменялись.
